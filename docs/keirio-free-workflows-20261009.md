# 無料枠向け実務機能の実装・検証

## 利用方法
- ログイン後の「実務管理」: 確認待ち、税理士レビュー、証憑、変更履歴、締め・提出、定期下書き、入力ガイド。
- 「アカウントの安全管理」: メール確認状態、端末一覧、他端末終了、全端末ログアウト、ログイン/レビュー/期限/処理エラーの通知。
- 仕訳候補は既存の確定仕訳から照合し、日付と本人の確認を経て下書きにする。外部AI評価を装わない。
- 定期処理は明示操作で対象月の下書きを生成する。月次の同一ルールは一度のみ。確定・請求書送信は自動化しない。

## 無料枠の境界
- 新規R2、外部アカウント、有料サービスを有効化していない。
- 原本: 1件256KiB、事業者5MiB/100件、全体50MiB/1000件。原本は圧縮・加工しない。非表示の原本も保存枠に含む。
- 履歴: 全体50MiB/50,000行。UTF-8の実バイトで計算。変更の前に操作主体を記録し、容量を予約する。同事業者の同時変更は409で再試行を案内し、枠不足は変更前に拒否。余裕を予約するため上限直前では早めに拒否する。
- 業務JSON変更は1回32KiB以内。定期登録20件まで、1回20件まで。ワークフローの書込はユーザー60回/時。
- メールは既存Resend設定がある場合のみアプリ全体90通/UTC日。現在本番の秘密設定一覧にResendのキーがないため、実送信・本人確認メールは未稼働。鍵の値は読んでいない。
- FREE_TIER_MODE=trueで外部AI読取を停止。手入力・原本保存・過去仕訳候補は利用可能。
- 既存のStripe契約・料金・Cloudflareアカウントプランは変更していない。他サービスとの共有枠や既存料金まで無条件に0円と保証しない。

## データ保全
- 保存済みユーザー・会計データ・既存共有・白緑デザインを維持。
- 事業者最終締日までの会計更新をD1トリガーでも禁止。再開はオーナーのみ、理由必須。
- 締め済み請求書の翌月入金は、元の金額等を変えないPAID遷移のみ許可。単発の入金クレーム・仕訳・状態を一括処理し、再実行で重複計上しない。
- 入金消込済みの仕訳/請求書は直接変更・削除せず、訂正は別取引として記録。
- 親削除で消える子明細も、消える前に変更履歴へ保存。
- SQLトリガー履歴は確定した前後状態、API_REQUEST履歴は操作主体と受付内容を表す。失敗した受付を確定変更と表示しない。
- 提出JSONには業務データ・原本・締め状態・定期実行結果・入金クレームを含む。パスワード/セッション秘密情報は含まない。
- 復元はローカルQAの隔離DBだけで検証。本番復元APIなし。法令適合や外部監査済みを保証しない。

## レビューと判断
独立したコードレビューで入金の部分書込・親子削除・受付後監査・文字数計算の問題を発見し、失敗再現と回帰で修正。
判断:無料原本保存を既存D1の小容量に制限し、R2新規契約をしない。代償は大きい画像を保存できないこと。
判断:定期処理を明示実行/下書きに限定。代償は完全無人の請求・送信でないこと。
判断:履歴は受付記録と確定変更の別記録。代償は履歴に失敗した受付も載ること。
判断:メール/外部監視を未設定と明示。配信実設定と全基盤停止通知は別途必要。
